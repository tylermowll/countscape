# v0.2.0 release validation

Date: 2026-10-29.

## Maintainer-authorized publication exception

The maintainer explicitly authorized publishing v0.2.0 using automated
validation, with the fresh Ubuntu 26.04 GNOME/Wayland baseline recorded as
**NOT RUN** for Python 3.15.2 and Pillow 13.0.0.

This exception applies only to v0.2.0 and the live baseline gate in the
[release checklist](../release-checklist.md). It does not replace that gate for
future releases or establish additional live-platform compatibility.
Historical platform evidence remains limited to the release and configurations
recorded in the [readiness audit](public-repository-readiness.md).

## Automated validation

The dependency update in [PR #18](https://github.com/tylermowll/countscape/pull/18)
passed the full release checks from a clean clone using Python 3.15.2, uv 0.13.6,
and Pillow 13.0.0:

- 348 tests passed, with 90.39% branch coverage against the 90% gate.
- Locked environment synchronization, formatting, lint, and local Markdown
  links passed.
- Worktree, complete reachable history, wheel, and source archive passed the
  privacy checks; package members and metadata were reviewed.
- Both distributions installed outside the checkout and exposed the expected
  version and help commands.
- GitHub CI and CodeQL passed on the merged commit.

The follow-up dependency-submission tests brought the local suite to 359 passing
tests with the same coverage result. The graph converter was also exercised
against the actual lock: both submitted manifests contain ten external
dependencies, with Pillow 13.0.0 as the only runtime dependency. The release
workflow repeats validation and builds the exact artifacts used for both
publication channels.

## Dependency monitoring

All 71 existing Dependabot alerts identified Pillow versions below 13.0.0 as
vulnerable and 13.0.0 as patched. The new requirement and lock exclude those
ranges. Dependabot's current updater rejects Python 3.15; the dedicated graph
workflow submits the locked project dependencies and development groups from
`uv` exports. Isolated build requirements are outside those exports.

No alerts are dismissed to hide stale results. Version upgrades for Python
dependencies require a reviewed manual lock refresh until Dependabot supports
the new interpreter; its GitHub Actions updates continue normally.
